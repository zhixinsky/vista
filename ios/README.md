# CarVista 0.4.0

制作页简化为“选择照片 → 生成壁纸文件 → 替换 CarPlay 壁纸”。最多选择 6 张，每张自动保存深色与浅色两个版本。默认不需要调整，标准模式可拖动/双指缩放裁剪，所有模式支持旋转、翻转与还原。

| 模式 | 输出尺寸 | 处理方式 |
| --- | --- | --- |
| 自动 | 已检测的主要缓存尺寸；未检测时 1920 × 810 | 完整照片居中，照片自身模糊背景填满 |
| 标准 | 1440 × 810 | 照片铺满裁剪 |
| 宽屏 | 1920 × 810 | 完整照片居中，照片自身模糊背景填满 |
| 大联屏 | 2560 × 810 | 完整照片居中，照片自身模糊背景填满 |
| 原尺寸 | 每张照片自己的像素尺寸 | 不缩放、不裁切、不用模糊填充；旋转或翻转后宽高随之变化 |

模糊背景先延伸边缘再模糊，不引入黑边；清晰前景始终等比例。预览和保存共用渲染器。生成后直接写入，不在替换阶段再次缩放；保留备份、目标身份检查、过期文件拒写与回读校验。车机最终显示效果仍需实测。

应用已更名为“CarVista”。为保持覆盖升级和已有数据兼容，工程名、Bundle ID 与 App Group 保持原值。第三方模块的作者署名与许可证保持完整。

面向自有 iPhone 的 CarPlay 自定义壁纸实验版本。用户已反馈旧版在 iOS 27.2 / iPhone 16 Pro Max 上成功替换；本版新排版效果仍需车机实测，不能将编译通过等同于所有设备兼容。

## 功能

- 首页统一为“壁纸 / 历史记录 / CarPlay 壁纸缓存 / 设置”，首次使用四步指南。
- App 图标、启动画面与一致的品牌样式；图标源文件与生成提示见 Design/。
- 未连接车机也能选图、预览并制作本地 CPBitmap，自动生成深色与浅色版本。
- 深浅色文件在历史中合并展示；支持详情预览、分享、重命名、删除单条与清空本地记录。
- 照片和调整草稿自动保留，移除照片不会删除历史或恢复备份。
- 基于 WQFiles / worse_query 的 App Group 访问后端，快速定位和可停止的完整容器扫描。
- 仅识别 `com.apple.CarPlayWallpaper`，在其 Library/Caches 下发现实际 CPBitmap，不写死颜色或 `-14` 后缀。
- 读取目标尺寸、深浅色分类；解码失败或尺寸异常时禁止替换。
- 相册选图、拖动定位与缩放预览；生成并回读验证 CPBitmap。
- 应用时直接写入生成文件，不进行二次尺寸处理。配对的深浅色可一次应用；多文件操作逐个执行，部分失败会明确报告成功数量，不宣称全部成功。
- 写入前备份，原位写入并回读校验；拒绝扫描后已变化的目标；备份历史恢复。
- 诊断报告导出。若访问或格式不兼容，会明确失败，不假装成功。

## 安装与测试

GitHub Actions 产物为 `CarVista-resign.ipa`。它带有 ad-hoc 签名和 App Group entitlement，**不能直接安装**，必须通过签名工具授予有效 App Group 并重新签名。AltStore / SideStore 等支持 App Group 的流程可作为选择；仅保留 entitlement 文本不代表具备权限。普通企业通配符 profile 通常不满足条件。

1. 签名安装后，在说明页确认 App Group 不为空。
2. 停车后连接 CarPlay，切换几张内置图片壁纸生成缓存。
3. 打开“壁纸”选择照片与尺寸模式，点击“生成壁纸文件”，自动生成并保存深色与浅色版本。
4. 在保存后的详情或历史记录中选择“应用到 CarPlay 壁纸”，应用会查找缓存。未找到时可“继续查找”；选中目标后确认应用。
5. 写入后点“重启 CarPlay → 重载界面，让壁纸生效”，尝试通过 NeoSpring 的 WebKit 方式重载系统界面。它不是官方重启接口，iOS 27.2 上的兼容性与 CarPlay 刷新效果待真机验证。没有效果时手动重启 iPhone。
6. 如需还原，扫描确认容器后选择备份，恢复后重启 iPhone 并连接 CarPlay 验证。

系统容器访问受版本、签名和权限影响。若缓存格式已不再是 CPBitmap，此版本会报告未找到可识别文件，不会修改未知格式。不要卸载应用来“恢复壁纸”：卸载会删除本应用内备份，而系统缓存修改可能仍然保留。

## 构建

macOS + Xcode + XcodeGen：在 ios 目录执行 `xcodegen generate`，打开 `CarVista.xcodeproj`。本地真机签名需为自己的 Bundle ID 创建并授予 App Group。

`.github/workflows/ios-diagnostics.yml` 在 main 更新后自动编译。流水线先运行裁剪/扫描测试和上游文件写入与容器解析回归测试，再编译真机 arm64 应用，打包并生成 SHA-256。

## 测试边界

主机测试覆盖裁剪覆盖范围、比例保持、文件变化比较、符号链接排除、缺失目录错误、旧版历史兼容，以及上游备份/写入/恢复/解析回归。模拟器 UI 测试打开四个首页入口和首次指南并导出截图。这些测试不会修改手机系统容器。

尚须真机验证：实际签名权限、令牌获取、容器识别、私有 CPBitmap API 的当前行为、断电情形和车机加载结果。原位写入保留 inode，但不能保证面对突然断电或系统并发写入时完全原子化。

仓库中原作者的旧版 IPA 属于历史产物，不属于当前工程构建结果。

内置 5 张 6008×934 整屏壁纸。点击后拖动分界线或逐像素微调，只截取右侧区域；默认中点不代表真实车机边界，确认后记住位置。选用后自动切换原尺寸，不缩放、不融合。旧融合设置自动迁移到原尺寸。

界面重载实现：仅用户主动点击触发；写入期间禁用；非持久 WebKit 数据存储；10 秒后停止尝试；进入非活跃状态或关闭页面时清理；模拟器不加载触发页面。不会自动重复执行，也不会以黑屏或进程退出作为壁纸刷新成功的证明。超时清理是尽力而为，若系统渲染进程阻塞，不能保证严格在 10 秒内响应。
